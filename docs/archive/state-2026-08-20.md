# Where conch stands — 2026-08-20

## Shipped and running on your Mac and phone

**Phases 1 and 2 are done**, verified in source rather than from commit
messages (that check went wrong twice, so every claim below names a file).

Recently, and all live:

- **Resume by search**, both devices, showing the names Claude Code shows —
  `custom-title` beats `ai-title` beats the first message, read from a 64KB
  tail because the current name lives at the END of a 158MB transcript.

  calls and 1 other were headless routines wearing their system prompts as
  names.
- **The capability inspector** — session `⋯` → "What this session carries…".
- **Sessions start with permissions bypassed**, because you asked; ships off.

  converted into a choice.

  with a retry, and hides controls that cannot work while disconnected.

## The two bugs worth knowing about

**conch was answering questions you did not answer.** "actually neither, lets
talk about it first" was classified as "Use Postgres" — any "first" anywhere
selected option one. Also "give me 2 minutes" → option two, and "give me a
second to think" → "Ask me later", because "me" belonged to exactly one option.

**Two of your MCP servers do not work and conch showed them as fine.**
`playwright` is rejected for this project; `posthog` has its plugin set to
`false` in `settings.json`. The inspector led with "a definition exists on
disk" whenever one did, so a switched-off server looked identical to a live
one. Both now show a red **disabled** chip.

## What is left, ranked

1. **Plugins, skills, MCP and the slash-command palette** — read-only half is
   built; per-kind metadata (transport, version, marketplace, skill visibility,
   tool approval mode) is the next increment.
2. **Phase 4, performance** — Kokoro by mode, whisper pre-warmed on a signal.
   ~1.3GB.
3. **The app owns its daemon outright** — `daemon-identity.ts` is written and
   tested; wiring it in is the other half. Parked by you.
4. **Multi-select by voice** still returns one option; the apps submit a set.
5. **Blocked on ten seconds of your hands**: approvals and checkpoint/revert.
6. **Phase 3, the feed** — deliberately last, and a VIEW over what exists
   rather than a second product.

## Newly captured, not started

- **The write pass.** Toggling and permissions. More is writeable than the plan
  assumed: Claude's `enabledPlugins` map and per-project MCP lists, Codex's
  per-server `enabled` and per-tool `approval_mode`. Every control must read
  "for the next session" — none of it affects a running host.
- **Discovery and the unified marketplace** (`docs/marketplace-vision.md`).
  Skills, plugins, marketplaces, MCP servers, workflows/loops, prompt
  templates, with per-platform filters. Note: the last three are not things
  either agent packages today — the most interesting part of the idea, or a
  scope trap.
- **Per-session configuration at START time**, which sidesteps "cannot change a
  running host" rather than fighting it. Probably the strongest version of the
  write pass.
- **Subagents nested under their session**, folder-style, with an open question
  about how you reach one from inside a conversation.
