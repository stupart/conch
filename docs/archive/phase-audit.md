# Phase 1 and Phase 2 source audit

Audited 2026-08-18 on branch `feat/relay` at `e1fc601`.

## Verdict

The roadmap is wrong: neither Phase 1 nor Phase 2 is done under the stated all-surface standard.

- **Phase 1 is not done.** The terminal still has no composer and its mic still sends directly to the session. The Mac's new composer-dictation path can also put returned text into the wrong session's draft.
- **Phase 2 is not done.** The terminal cannot start or close sessions, shows neither context nor agent identity, and does not render the structured question it already receives. Multi-select questions are also broken on the two apps that do render them.
- The iPhone-specific backlog is stale in the other direction. It now has a searchable resume picker and a restore path; `docs/backlog.md:102-110` still says it has neither. The resume picker is at `mobile/conch-ios/conch-ios/LedgerView.swift:550-600`, carries the picked session's folder at `mobile/conch-ios/conch-ios/LedgerView.swift:613-634`, and restore is reachable at `mobile/conch-ios/conch-ios/LedgerView.swift:71-104`.

This is a source audit, not a live-session test. I did not start or restart the daemon, send a control message, touch a session, or exercise Terminal automation. I traced the current Bun/TypeScript daemon and TUI, both SwiftUI apps, and their focused tests. The isolated relevant test set passes (78 tests), but the tests themselves miss two broken paths described below.

### Verdict key

- **DONE** — the surface has the complete claimed behavior in source.
- **PARTIAL** — useful behavior exists, but a stated path or supported case is missing or broken.
- **NOT DONE** — the surface lacks the claimed interaction.
- **SCOPED-OUT** — the backlog expressly does not require that surface to implement the item.

The terminal scope is narrow, but not infinitely elastic. It owes “read, answer, interrupt, dismiss, restore, switch mode” and is expressly excused only from image attachment, artifact rendering, and the phone audio lease (`docs/backlog.md:159-164`). That text does **not** scope a terminal composer out of the explicit Phase 1 claim that every surface has one.

## Broken, not merely missing

These are worse than parity gaps because the surface presents a feature that can do the wrong thing.

1. **Mac composer dictation loses its owning session.** The request has `sessionId` (`mac-app/conch-mac/ConchSocketClient.swift:69-80`), but `publishDictation` publishes only `{ text, id }` (`src/status.ts:1519-1536`). The Mac applies that global result to `focusedRow` at receipt time (`mac-app/conch-mac/DashboardView.swift:1604-1615`). If focus changes while capture/transcription completes—or the live focus falls back before the next app poll—the words can be appended to another session's draft. The current test actually bakes in the unsafe behavior by asserting append-to-`row.id`, without asserting that the row is the original target (`test/compose-dictation.test.ts:52-62`).

2. **Multi-select questions advertise multi-select and submit single-select.** The canonical model includes `multiSelect` (`src/conversation.ts:382-420`). Both apps draw square selection controls, but tapping one immediately injects its label (`mac-app/conch-mac/ConversationStackView.swift:193-202`; `mobile/conch-ios/conch-ios/ConversationStack.swift:224-258`). Voice classification also returns exactly one option index (`src/dictation-reducer.ts:440-443`). The Phase 2 tests cover only ordinary one-choice questions (`test/phase2-daemon.test.ts:160-200`, `test/ios-phase2-source.test.ts:81-88`, `test/mac-phase2-source.test.ts:95-110`).

3. **The terminal receives structured questions and then drops them at rendering.** `PanelModel` carries `conversation` and `conversations` (`src/panel.ts:128-140`), and the daemon populates both (`src/daemon.ts:2314-2318`). The theater renderer uses only flattened `reply` or `preview` (`src/status.ts:665-689`, `745-775`). For Claude, an outstanding tool call explicitly clears `lastAssistantText` (`src/snippet.ts:251-267`), so an `AskUserQuestion` can leave the content pane empty or on an older reply while the ledger merely says “needs a response.” The voice classifier exists, but the surface withholds the question and option labels needed to use it.

## Ranked fixes

Ranked first by risk of sending the wrong user intent, then by how directly the gap breaks “one interaction model,” then by daily-use value.

1. **Preserve the target session on Mac composer dictation.** Publish `{ sessionId, text, id }` and append by that id, not current focus. This is an existing control capable of placing words under the wrong agent, so it outranks every missing control.
2. **Finish the question contract, including multi-select.** Add selection accumulation plus explicit submission on Mac and iPhone; make the daemon voice path capable of an unambiguous set. Today a control visually promises multiple choices and commits the first tap immediately.
3. **Render and operate structured questions in the TUI.** The data already crosses the daemon boundary. Showing it and adding keyboard option selection would satisfy the terminal's expressly owed “read” and “answer” behavior, instead of requiring the user to know an invisible question before voice classification can help.
4. **Give the TUI the same composer-bound mic contract, or explicitly rewrite the scope.** At present Mac and iPhone mics fill editable per-session drafts while terminal space sends directly. That is the clearest remaining product split in Phase 1, and the current terminal scope does not expressly exempt it.
5. **Expose session start and clean close in the TUI.** The daemon lifecycle machinery already exists; only the terminal presentation is missing. Until then “start and close sessions from conch” means “from the apps,” not all three surfaces.
6. **Render agent identity and context in the TUI.** Backend is already present in `PanelRowModel`; context needs to be carried into it. These are lower-risk read-only gaps, but their absence makes the terminal ledger materially less informative than both apps.
7. **Actually retire the mute vocabulary, or describe it honestly as a compatibility alias.** Remove the CLI/MCP/wire aliases once compatibility permits. Until then the roadmap must not say mute was retired across those layers.
8. **Bring fresh-session folder selection to iPhone.** This is not required to satisfy the narrow “can start” item, but it is the remaining real part of the backlog's phone-parity bullet: new phone starts pass no `cwd`, while Mac starts let the user choose one (`mobile/conch-ios/conch-ios/LedgerView.swift:624-634`; `mac-app/conch-mac/ContentView.swift:378-398`).

- `docs/backlog.md:94` says Phases 1 and 2 are finished, then `docs/backlog.md:98-101` calls composer-bound mic behavior “the last Phase-1 idea” and deferred. Current Mac source has since implemented that path, but the contradiction shows why the blanket status is not credible.
- `docs/backlog.md:102-110` must be refreshed: searchable phone resume and phone restore are shipped; fresh-session folder selection is the one listed phone gap that remains.
- `docs/backlog.md:26-28` must not say mute is retired from socket/MCP/CLI/persistence while the aliases remain in `src/hook.ts:27-29`, `src/cli.ts:426-434`, and `src/mcp.ts:652-669`.
- `docs/backlog.md:37` says app errors go into “the daemon's log.” The daemon actually appends them to the separate, durable `errors.jsonl` store (`src/app-errors.ts:6-23`, `46-71`). The feature is real; the destination in the roadmap is not.

Passing tests do not override these source verdicts. The audited isolated suite is useful evidence for the paths it covers, but commit messages and source-presence tests are not evidence that an interaction is complete across three surfaces.
