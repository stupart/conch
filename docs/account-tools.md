# Account tools and model catalogs

Settings → Plugins & MCP is shared by the Mac and iPhone apps. Choose Claude Code or Codex, then the account (email and profile label). The iPhone sends the same authenticated control requests to its connected Mac; paths and local MCP commands refer to that Mac.

The library lists plugins discovered in registered profiles, plus the local Conch marketplace and Blueprint Studio's official Claude marketplace. Install registers the source before installing the plugin through the provider CLI, with the selected CLAUDE_CONFIG_DIR or CODEX_HOME. No account credentials are copied. Custom plugins accept a marketplace source and name@marketplace as separate fields, avoiding accidentally combining slash commands. Removing a Claude plugin preserves its persistent data.

Plugins can be enabled, disabled, or removed. Skills are listed with their owning plugin. MCP servers can be added using an HTTP URL or an executable and separate arguments, and user-defined servers can be removed. Plugin-owned, project, and managed definitions are not editable from this account screen. Codex supports account-level MCP enable/disable; Claude's MCP switches are project-specific, so use /mcp in the relevant session. Authentication remains with the provider and may require browser sign-in. Installation/configuration is not evidence that a running session has loaded a tool: start a new session, use Claude's /reload-plugins, or restart an existing session as appropriate.

Mutations run asynchronously in the daemon, one at a time per account, with request-ID deduplication for that daemon lifetime. The UI polls read-only status. On a lost connection it asks the user to refresh rather than resubmitting an install. Each provider command has a 90-second limit; timeout does not imply rollback, so the next inventory read is authoritative. The daemon does not forward command output, credentials, environment values, or MCP arguments to the UI. Toggle writes use the existing validated atomic config writer and backups.

Model choices are discovered from Claude's initialize control response and Codex's model/list app-server protocol, without submitting a prompt or starting a turn. Catalogs are cached per account for five minutes; discovery failures retain the last successful catalog or the existing file-based fallback. Both apps use the selected session's account catalog, preserving provider model IDs and supported effort levels. An older running CLI may offer fewer models than the current CLI; the session picker refuses unavailable choices instead of selecting a different explicit version.

A terminal button appears beside the session title whenever the daemon reports a revealable terminal, independently of deliverables. On iPhone it raises the terminal on the connected Mac.
