# What the daemon does to the rest of the Mac

Audited 2026-09-11 because Tyler asked: *"see if any daemon rules might be
globally affecting stuff on the computer? like closing mic when speaking or
something like that? or transcribing or u name it. if so we may need to move
more to an app-based approach instead of a daemon."*

Source audited at `238bcdd` (main). Live evidence is from the daemon that was
running while I read: pid 69656, spawned by `/Applications/conch.app` at
00:52:55, `/tmp/conch-daemon.log` (906 lines since 9/8), `ps`, `lsof`,
`launchctl`, `codesign`, and the files under `/tmp`, `~/.config/conch`,
`~/.cache/conch` and `~/.claude`. Nothing was started, stopped or changed.

**The short answer.** Nothing conch does closes, mutes, or takes over the
microphone or speakers for other apps — macOS shares both, and conch only ever
opens its own streams. The things that DO reach outside conch are: (1) it
*types* into windows with AppleScript, and the setting that is supposed to
gate that is dead because the app forces it on; (2) it *raises* a Terminal
window on every announced turn by default; (3) its hooks and its MCP server
load into **every** Claude Code session on the machine; (4) it listens on
`0.0.0.0:8674` in plaintext when the phone is on; (5) it speaks and rings
through the default output at any time in auto mode, mixed over whatever else
is playing. Most of these are the daemon doing its job; two of them (blind
typing and the forced keystroke fallback) should not exist in their current
form, and none of them get better by moving into the app — the app already IS
the responsible process for every permission that matters. What the app can
add is visibility: which permissions are actually granted, and a refusal to
type when the wrong window is in front.

## Where the Mac was during the audit

Manual mode, persisted (`~/.config/conch/state.json` → `{"paused":true}`).
Settings file: `phone: true`, `phone-relay-url` set, `meeting-autopause:
true`, `bypass-permissions: true`; everything else default. Running: the app
(93 MB, 0–7 % CPU sampled), the daemon (206 MB RSS), and eight `bun cli.ts
mcp` processes — one per open Claude Code session, including the Claude
desktop app's. **Not** running: `sox` (no mic open), `whisper-server`
(idle-unloaded at 01:12:57), any Kokoro worker (mlx-audio was never found on
this Mac until #160; the daemon has said "voices via say" at every start since
9/8). No launchd agent for conch exists; the app owns the daemon. The Mac's
mic opened twice in the whole log (9/9 17:06 and 17:08) and not at all today.
Today's two "heard" lines were phone-transcribed and typed into a Terminal
session by AppleScript.

Scope words used below: **interacting** = only while you are deliberately
using conch (a wake, a send, a button); **per turn** = whenever a watched
session finishes a turn in auto mode; **always** = for as long as the daemon
runs, regardless of mode.

| 5d | **Agents can change the mode.** `conch_mode resume` carries no origin, so any session can put the Mac back into auto — mic and voice included — while you are in a meeting you silenced it for. | `mcp.ts:672-680` | The `origin: "agent"` tag that protects `conch_wake` does not exist for mode changes or `conch_speak`. |

## Would the app be a better place for any of this?

The premise to test is that the app "holds the mic entitlement and can use
per-app audio sessions, TCC-scoped permissions and a visible UI". On macOS the
first is already true of the daemon (TCC attributes a child's access to the
responsible app — `docs/architecture.md`, "Whoever parents the daemon owns its
microphone permission"), the second does not exist (`AVAudioSession` is iOS;
macOS has CoreAudio device ownership, which is shared, and no third-party
ducking), and the third is real. So, item by item:

| item | verdict | why, concretely |
|---|---|---|
| 1a sox / the mic | **app would help — modestly** | Sharing does not change: CoreAudio input is shared for every process, and hog mode is the one thing you must not do. What an in-process `AVAudioEngine` input node gives that sox cannot: `AVCaptureDevice.authorizationStatus(for: .audio)` so a missing grant is a visible state instead of thirty seconds of silence; an input tap that dies with the process (no reparented sox holding the mic after a crash); level metering without a second recorder (kills 1c's extra sox). The Bluetooth/HFP effect is identical in either process — the only fix is choosing an input device other than the headset, which is a setting either can offer. Equal-and-cheaper alternative: keep sox, add a `pgrep`-style reaper for orphaned `sox -d` children of a dead conch, as D3 did for whisper. |
| 1b meeting-autopause | **no difference** | It is already a CoreAudio property read. Both the daemon (via `bun:ffi`) and the app can replace the 2 s poll with `AudioObjectAddPropertyListener` and widen it from the default device to every input device. The widening is the change that matters; where it runs is not. |
| 1c barge-in | **no difference** | Off. If it ever comes on, see 1a. |
| 2a–2c TTS and cues | **no difference** | `say`, `afplay`, `AVSpeechSynthesizer` and `AVAudioPlayer` are all plain CoreAudio output clients. macOS offers nothing to duck or pre-empt other apps' audio. The app could pick a specific output device (the built-in speakers while a call owns the headset) — so could the daemon, through `say -a` / `afplay` cannot, so this is the one small edge — but the behaviours that actually stop conch talking over a meeting (manual mode, meeting-autopause, away) are policy, and policy lives in the daemon. |
| 2d the invariant | **daemon is the right place** | It protects the loop from itself and is enforced by the serial queue. Splitting speech and mic across two processes would make it harder to keep, not easier. |
| 3a tmux | **daemon is the right place** | It is exact and unfocused. The improvement is to make it the *only* typing route by launching conch's own sessions inside tmux (`startTerminalSession` could wrap the command); that is daemon/CLI work. |
| 3b focused typing | **app would help — for the guard, not the typing** | Synthesising keystrokes needs Accessibility whichever process posts them; `CGEvent.post` from the app is no safer than `System Events keystroke`. What the app can do better is check, right before typing, that `NSWorkspace.shared.frontmostApplication` is Terminal and the AX-focused window is the tty's tab, and refuse otherwise — sub-millisecond, no 4 s osascript timeout — and show `AXIsProcessTrusted()` / `AEDeterminePermissionToAutomateTarget` in Settings with a deep link to the System Settings pane, so "automation-permission-denied" is a row in the UI instead of a clipboard surprise. Add `NSAppleEventsUsageDescription` to Info.plist regardless. Also, independent of process: stop forcing `CONCH_KEYSTROKE_FALLBACK=1` from `DaemonHost.swift:92` so the setting means something. |
| 3c blind typing | **delete it** | No process should type into an unknown window. The phone already refuses it; the voice loop should too. This is one line (`inject.ts:156` → clipboard). |
| 3d clipboard | **no difference** | `NSPasteboard` vs `pbcopy`. Either could save and restore the previous contents; neither does. |
| 3e reveal-on-turn | **no difference in behaviour; app slightly cleaner** | In-app `AXUIElementPerformAction(kAXRaiseAction)` needs the same Accessibility grant and avoids an osascript spawn per turn. The real question is the default: raising a window on every turn is the kind of thing that should be opt-in, or at least off while the display is being captured (`CGDisplayStream`/ScreenCaptureKit clients are not enumerable by third parties, so the honest answer is a setting, not detection). |
| 3f open/close Terminal | **no difference** | Automation either way. tmux-hosted sessions would replace the Ctrl-D keystroke with `tmux kill-session`. |
| 3g the app's own focus steal | **already in the app** | Same typing-grace gate; fine. |
| 4a–4b files | **no difference** | Path choices. `chmod 600` the hook log; consider `~/Library/Caches/conch` over `/tmp` if the app ever sandboxes. |
| 4c hooks | **no difference — it is a Claude Code fact** | Hooks in `~/.claude/settings.json` are global by design; nothing in the app changes that. The fast returns already bound the cost. A per-project opt-out would be a hook-side check (a marker file in the cwd), not an app feature. |
| 4d plugin + MCP | **no difference — and the policy fix is in the MCP** | One MCP process per session is how Claude Code loads plugins. Tag `conch_mode` and `conch_speak` with `origin: "agent"` and let manual mode hold them, exactly as `conch_wake` is held today. |
| 4h LAN bridge | **app would help — a little** | An `NWListener` in the app gets the Local Network TCC prompt (already declared in Info.plist), Bonjour, and TLS with a device certificate for free; the daemon can add TLS too, and can bind to the Wi-Fi interface instead of `0.0.0.0`. The gap is TLS, not the process. |
| 4i relay, 4j whisper, 4k GitHub, 4l Anthropic, 4m open, 4n ioreg | **no difference** | 4j: an app could swap whisper for Apple's on-device `SpeechAnalyzer` (macOS 26 is what this Mac runs) — zero resident memory, a TCC "Speech Recognition" prompt, system-managed model — but that is a transcriber decision with an unknown quality cost against large-v3-turbo, not an ownership one. 4n: the app already reads HID idle through `CGEventSource` with no spawn (`ConchMacApp.swift:371`); the daemon can call the same C function through `bun:ffi` and drop `ioreg`. |
| 4o idle cost | **no difference** | The models weigh what they weigh in whichever process loads them; D1/D2 already unload both. The MCP servers belong to Claude Code's plugin loader. |

**Net.** Moving behaviour into the app buys three things: a pre-typing focus
guard, honest permission state in the UI, and (if we ever want it) an input
tap that cannot outlive the process. It does not buy audio isolation — macOS
does not offer any — and it would cost the one property the daemon's design is
built on, the serial queue that keeps the mic and the voice from overlapping.
The daemon is the right shape; a few of its rules are wrong.

## The three changes I would make first

1. **Make typing honest.** Delete the blind route (`inject.ts:156` → clipboard,
   like the phone), stop exporting `CONCH_KEYSTROKE_FALLBACK=1` from
   `DaemonHost.swift:92` and `install.ts:635` so `keystroke-fallback` is a
   real setting (default it to true if that is the wanted behaviour, but let
   it be turned off), and before every `keystroke` confirm the frontmost app
   is Terminal and the focused window is the tty's — abort to the clipboard
   otherwise. Add `NSAppleEventsUsageDescription` to the app.
2. **Let manual mode mean manual for agents too.** `origin: "agent"` on
   `conch_mode` and `conch_speak` (`mcp.ts:658-680`) so an agent cannot
   re-enable the voice or speak while you have silenced the Mac; widen
   `meeting-autopause` to every input device and consider defaulting it on.
3. **Shrink the global footprint by default.** `reveal-on-turn` off by
   default (or gated behind a visible toggle in the app header), `chmod 600`
   on `/tmp/conch-hook.log`, `CONCH_LOG_FILE` honoured by the inject debug
   log so tests stop writing ghosts, and a reaper for an orphaned `sox -d`
   whose conch is dead (the D3 pattern).
